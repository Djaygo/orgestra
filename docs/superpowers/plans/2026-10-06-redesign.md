# Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the whole interface (shell, home, results, talk, speaker, browse, discussion, report, errors) in a Google-style visual system with tokens, dark mode, predictions, filters, an embedded video player and a calmer stage, and finish with a before and after video.

**Architecture:** Plain CSS files built on one `tokens.css` of colour, type, shape, elevation and motion roles; Jinja macros for the shared components (icon, chip, avatar, talk card); a small `ui.ts` module (Vite entry, tested with vitest) for theme, shortcuts, the prediction combobox, copy link and list filtering; new server pieces (`/suggest`, `/browse`, result filters, highlight filter, embed URL, related talks, error pages). The old `app.css` stays linked as `legacy.css` until every page is converted, then it is deleted.

**Tech Stack:** FastAPI, Jinja2, htmx (with view transitions), TypeScript and Vite (one extra entry), vitest, Playwright for capture and demo, pytest, ruff, ty.

**Spec:** `docs/superpowers/specs/2026-10-06-redesign-design.md`

## Global Constraints

- Keep the Google look: white canvas, four-colour wordmark, pill search, Google blue (`#1a73e8` family) as the only action colour. Self-hosted Roboto variable (latin) from `/static/fonts`, never a CDN.
- Components use colour roles from `tokens.css` (`--surface`, `--on-surface`, `--primary`, ...), never raw colours. Colours are `oklch()` through `light-dark()`; `:root[data-theme="light" | "dark"]` forces a scheme, otherwise it follows the system.
- Text contrast 4.5:1 and non-text contrast 3:1 in both themes (a test checks the role pairs); visible `:focus-visible` rings; 44 px touch targets on phones, 24 px minimum on desktop; a skip link first; one `h1` per page; no emoji icons, SVG sprite only; all motion off under `prefers-reduced-motion`.
- Behaviour kept: every route, form field, id and marker string the existing tests and the demo tour rely on (`form.new-post`, `article.post`, `details.reply`, `details.edit`, `details.history`, `form.report-form`, "(edited)", "restore this version", `class="diff-del"`, the `hit-matches`/`match` badges, `data-tip`, the slide link `#page=N`).
- Search ranking, data files and the discussion rules do not change.
- Features degrade without the Node build (no `dist/`): pages stay readable and usable; only the stage, theme toggle, predictions and shortcuts need it.
- Dependencies only through `npm install` / `uv add`; vendored font under `src/orgestra/static/fonts/` with its licence file.
- Line length 110; `uv run ruff check src tests scripts/fetch_slides.py`, `uv run ruff format --check`, `uv run ty check`, `npm run check`, `npm test`, `npm run build` must pass.
- Comments describe the current state only; never remove existing comments or docstrings.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; plain imperative style; no amending, no force-push; never `git add -A`, and never add `.superpowers/`, `demo*.mp4` or screenshots.

## Review Focus

- The theme must be applied before first paint and survive a reload; a stored value other than `light`, `dark` or `system` must be ignored, and a blocked `localStorage` must not break the page (Task 1).
- Predictions must never render unescaped user input, must be reachable and operable by keyboard, and `/suggest` must answer quickly with an empty list for a blank or one-letter query (Task 2).
- A video URL on any host other than the two known ones (including look-alikes such as `youtube-nocookie.com.evil.test` and plain `http`) must never become an iframe (Task 4).
- Highlighting must escape first and never create markup from a talk's text or the query (Task 3).
- Error pages must not leak exception text for a 500 and must keep the JSON answer for non-browser clients (Task 1).
